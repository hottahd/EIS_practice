## なぜ 1 冊なのか

**Colab はノートブック 1 冊ごとに新しい VM が立ち上がる。**
分冊にすると、開くたびに `pip install`（1〜2 分）と
**EIS の 94 MB のダウンロード**を繰り返すことになる。
1 冊にまとめれば、準備は**最初の 1 回だけ**で済む。

## 受講者に最初に伝えること（Colab の保存の挙動）

GitHub から開いたノートは**読み取り専用の一時セッション**として扱われる。

- **編集も実行結果も保存されない。** 残すには「ファイル → ドライブにコピーを保存」
  （`MyDrive/Colab Notebooks/` にコピーができる。以降は教材側の更新は反映されない）
- **仮想マシンが消えるとダウンロードしたデータも消える**
  （放置で数十分、使っていても無料枠では最長で半日程度）
- 消えても**上から流し直せば復帰できる**（既にあるファイルは取得し直さない設計）
- どうしても残したいなら `drive.mount('/content/drive')` で Drive に置く手もあるが、
  許可ダイアログを踏ませることになるので既定にはしていない

## 編集する人向け

### `.ipynb` を手で書かない

ソースは**章ごとに** `src/NN_*.py` に `# %%` 区切りの素の Python で書き、

```bash
python notebooks/build_notebooks.py     # src/*.py -> EIS_workshop.ipynb（1 冊）
```

で生成する。JSON を直接いじると差分もレビューも辛いため。
配布物は 1 冊だが、**ソースを分けておくと差分が読みやすく、
章ごとに検証もできる**。

生成時に、各章の先頭にある「インストール」「ブートストラップ」のセルは
**先頭の 1 組だけ**にまとめられる。

### 編集したら必ず検証する

```bash
python notebooks/verify_notebooks.py        # 配布物を通しで実行（約 100 秒）
python notebooks/verify_notebooks.py 03 04  # 編集中の章だけ（src/*.py）
```

**★ 引数なしの実行を必ず 1 回は通すこと。** 1 冊版は全章が
**1 つの名前空間**で動くので、章をまたいだ変数名の衝突は
こちらでしか見つからない。

Colab 専用セル（`!pip` などの shell/magic を含むもの）は自動で飛ばし、
飛ばした番号を表示する（何を検証していないかが分かる）。

### 途中から始めても動くようにしてある

観測データはその場で取得し（既にあれば何もしない）、章をまたいで使うもの
（22 輝線の強度、ラスターのフィット結果）は無ければ
**`scripts/workshop.py` がその場で作り直す**。
セッションが切れた後や、遅れて追いつく受講者でも困らない。

第 3 章と第 4 章は**同じフィット結果**を使う（`workshop.fit_region` がキャッシュする）。
2 度フィットすると 2 分余計にかかるため。

## モジュール 1: EIS とは何か / データを見る

**扱うこと**
- EIS は撮像分光器。スリットを動かしてラスターを作る。
  → 「1 枚の画像を撮る」のではなく「時間をかけて掃く」ことの意味
  （この観測は 62 分かけて 120" x 512" を掃いている。時間変化が混ざる）
- 2 つの波長帯 171–212 Å / 245–291 Å、~1"/pixel、~22 mÅ
- **観測プログラムによって使える輝線が違う**。テレメトリ制限のため
  スペクトルウィンドウは限られる。Ca XIV–XVII が入っているかが死活問題。
  - 今回の観測 `HPW021_VEL_120x512v1` は **HPW = Harry P. Warren**、
    論文著者自身が DEM 解析のために設計したもの。25 ウィンドウ。
- Level-0 → Level-1 較正（pedestal, dark, 不良ピクセル, 絶対較正）は
  現代では **NRL 配布の Level-1 HDF5 を直接取る**のが実質標準

**手を動かすこと**
```python
import eispac
eispac.download_hdf5_data(filename='eis_20110702_030712', local_top='data/eis')
h = eispac.read_wininfo('data/eis/eis_20110702_030712.data.h5')   # 25 ウィンドウ
cube = eispac.read_cube('...', 195.119)     # (512, 60, 24)
```
- `scripts/quicklook_raster.py` を走らせる → `figures/quicklook_region7.png`
- **Si VII（moss）→ Fe XII（ループ）→ Fe XVI/Ca XV（高温コア）で
  形が変わる**のを自分の目で見る。ここが講習会全体の動機付け。
- Ca XVII のパネルが Fe XII に似ているのはなぜか？ → ブレンドの伏線

**教えたい勘所**: 「EIS はスペクトルを撮っている。画像は自分で作るもの」

## モジュール 2: スペクトル線フィット

**扱うこと**
- 単一ガウシアン + 背景でフィットする。eispac のテンプレート機構。
- **成分の順番は波長順ではない**（受講者が確実に踏む地雷）:
  - `fe_13_203_826.2c` の第 0 成分は Fe XII 203.720
  - `fe_14_270_519.2c` の第 0 成分は Mg VI 270.394
  - `ar_14_194_396.2c` の第 0 成分は Mn X 194.327
  - `ca_14_193_874.2c` の第 0 成分は Fe X 193.715
  → `template['line_ids']` を必ず確認する
- **全ラスターをフィットすると遅い**: 1 輝線 30720 スペクトルで 95 秒。
  22 輝線なら 35 分。
- **論文の手順は「箱の中で平均してからフィット」**（Step 5）。
  こうすると 22 輝線で 8 秒。速いだけでなく S/N も上がる。正しい順番。
- 平均するときの注意: 欠損 (NaN) を平均に入れない。
  EIS は波長が空間位置ごとに僅かにずれる（軌道変動・スリット傾き）ので、
  箱が広いときは共通波長グリッドへの補間が要る。

**手を動かすこと**
```python
fit = eispac.fit_spectra(cube, tmplt, ncpu=4)     # まず 1 輝線を全ラスターで
inten = fit.get_map(component=0, measurement='intensity')
```
その後 `scripts/fit_box_spectra.py` で箱平均→22 輝線フィット。

**教えたい勘所**: 「輝線強度は測定値ではなくフィットの産物。何を仮定したか」

## モジュール 3: AIA/HMI と Fe XVIII

**扱うこと**
- `sunpy.net.Fido` で VSO からデータを取る。**VSO は登録不要**（JSOC は要登録）。

- `aiapy` で level-1 → level-1.5（`update_pointing` + `register`）、
  露光時間で割って DN/s
- **落とし穴**: level-1.5 化しても波長ごとに配列サイズが違う

- **Fe XVIII の分離**（論文 Appendix）
  - 94 Å は 7 MK の Fe XVIII を含むが低温線に汚染されている
  - 171 と 193 の混合で warm 成分を経験的に見積もって引く
  - **論文 Eq.(A1) の指数は誤植**。正しくは定数項つきの 3 次式。
    → `scripts/aia_fe18.py` の解説を読ませる
- **適用限界**: フレア中は不可（Fe XXIV が 193 に入る）、明るい moss でも破綻

**手を動かすこと**
`scripts/download_sdo.py` → `scripts/make_fe18_map.py`

## モジュール 4: 座標合わせと inter-moss 領域

**扱うこと**
- **EIS のポインティングには系統誤差がある**。今回は AIA に対して
  +8", −10" ずれていた。ヘッダを鵜呑みにすると箱の位置がずれる。
- 合わせ方: 温度の近い組（EIS Fe XII 195.1 と AIA 193、どちらも ~1.6 MK）
  の相互相関
- 相互相関の指標は**重なり領域ごとに正規化した Pearson 相関**を使う。
  全体で一度正規化すると重なりの小さいシフトで見かけの相関が上がる。
- **inter-moss 領域とは**: AIA Fe XVIII で明るく、AIA 171 の moss を含まない場所。
  ループの**頂上付近**を測るため。足元（moss）や冷却ループが混ざると
  活動領域全体のモデル無しには解釈できなくなる。
- **ここは自動化できない物理的判断**。指標で候補を出し、最後は図を見て決める。

**手を動かすこと**
`scripts/coalign_eis_aia.py` → `scripts/select_intermoss.py`

**教えたい勘所**: 「どこを測るかを決めるのが解析の本体」

## モジュール 5: 論文 Table 2 と答え合わせ ★講習会の山場

`scripts/compare_table2.py` で 22 輝線を論文と比較する。

**採用箱での結果（準備段階で確認済み）**

| 箱 | median | ばらつき | 15% 以内 |
|---|---:|---:|---:|
| y=[244:274], x=[32:40] | 0.89 | 0.10 dex | 13/21 |
| y=[246:269], x=[30:38]（論文の箱サイズ） | 0.93 | 0.12 dex | **15/21** |
| （参考）y=[200:230], x=[20:28] 適当に明るいところ | **0.96** | 0.26 dex | **5/21** |

**★ 一番下の箱に注意。median が最も 1 に近いのに、15% 以内は 5 本しかない。**
個々の線が上下に大きく外れて打ち消し合っているだけ。
→ **median・ばらつき・本数・温度依存の傾きを揃えて見ること。**

- Fe XI, Fe XII, Fe XIII, Fe XIV, Ca XIV, Ca XV が 0.87–0.95
- **同じ数字が SSWIDL (eis_prep + mpfit) でも小数第 2 位まで出る**ことを確認済み。
  「Python だから合わない」ではないと断言できる。

**「箱の選び方」を数値で診断する**

ratio の log T に対する**傾き**を見る:
- 傾き ≈ 0 → 論文と同じ温度組成の場所を見ている
- 傾き < 0（冷たい線が明るく熱い線が暗い）→ 暖かいループ寄りを選んでいる
- 傾き > 0 → 高温コア寄り

準備段階で、適当に選んだ箱は傾き −0.37、inter-moss 箱は +0.22 だった。
**受講者に何通りか箱を選ばせて、この傾きを比べさせる**のが良い演習になる。

**合わないものを議論する**（ここが一番勉強になる）

- **Ca XVII が 4.75 倍** → ブレンド。これは原因がはっきりしている（モジュール 8 へ）。
  論文どおりの拘束で解くと **0.77** まで下がる（準備段階で確認済み）。
- **Si VII 275.368 が 0.39** → **未解決**。ただし範囲は絞れている。

  他論文の inter-moss 領域と Fe XII 195.119 に対する比で並べると:

  | | SiVII/FeXII | FeXVI/FeXII | SXIII/FeXII |
  |---|---:|---:|---:|
  | Tripathi+2011 inter-moss A | 0.0477 | 0.4381 | 0.4704 |
  | Tripathi+2011 inter-moss B | 0.0230 | 0.2372 | 0.2916 |
  | Tripathi+2011 inter-moss C | 0.0848 | 0.4763 | 0.5267 |
  | Warren+2011 (ApJ 734,90) | 0.0319 | 0.7846 | 0.5793 |
  | Warren+2012 region 7（論文） | 0.0583 | 0.5498 | 0.4029 |
  | **我々** | **0.0240** | **0.3620** | **0.3078** |

  一見「実在の inter-moss 領域どうしで 3.7 倍ばらつくから正常」と言いたくなる。
  **しかしこれは誤り。** Tripathi+2011 は**別の活動領域**であり、
  「このラスター内で論文の組み合わせが実現できること」を保証しない。

  **★ 検証（この演習が一番教育的）**: 230 箱を総当たりして
  `r_X / r_FeXII195`（1 なら論文と同じ比）を計算すると、
  **`22輝線の15%以内 >= 12` かつ `SiVII比 >= 0.8` を満たす箱は 0 個**。
  Si VII を合わせにいくと Si X 1.85、Fe XIV 1.67、Ar XIV 0.28、
  Ca XVI 0.15 と高温側が壊滅する。

  **さらに AIA が独立に決着をつける**:

  | 箱 | AIA Fe XVIII | 対論文 | SiVII比 |
  |---|---:|---:|---:|
  | Si VII が合う箱 | 1.160 | **0.161** | 1.125 |
  | 我々の採用箱 | 6.639 | **0.922** | 0.36 |
  | 論文の箱（図から実測） | 6.811 | **0.946** | 0.43 |

  Si VII が合う箱は **AIA Fe XVIII が論文の 6 分の 1**。
  そこは moss であって inter-moss ではない、と EIS と独立に言える。

  → **論文の Si VII 値は、同じ Table 2 の AIA Fe XVIII 値と整合しない。**

  **教訓**: 「Aで説明できる」と言ったら、必ず
  **「Aが正しいなら成り立つはずの予測」を立てて検証する**こと。
  今回は「自然なばらつきなら、このラスター内に論文と同じ組み合わせの
  箱があるはず」という予測が反証された。反証したのは独立な AIA の測定。

  潰した容疑（受講者にも同じ手順を踏ませたい）:

- **Fe XVI (0.62), S XIII (0.72)** → 「長波長側の感度劣化」は**成立しない**。
  同じ長波長チャンネルの S X (0.96)、Si X (1.08)、Fe XIV (0.91/0.94)、
  Fe XV (0.88) は合っている。隣り合う波長（Si X 258.375 と Fe XVI 262.984）で
  1.08 と 0.62 に分かれるので、波長依存の較正では説明できない。
  → こちらも Si VII と同じ状況。単独なら箱で 1.0 に届くが、
    そのとき他の線が壊れる。**箱では説明できない。**

- **Fe XIII の 2 本が DEM から 1.3-2.8 倍ずれる** → **原子データ側の既知の問題**。
  Warren+2011 でも R = 1.87 / 1.90、Warren+2012 でも 1.80 / 1.82。
  **論文自身が同じずれを報告している**ので、我々の解析の問題ではない。
  密度診断に使われる線なので、密度の仮定の話につなげられる。

**★ 決定的な事実（受講者に必ず見せる）**

  | | 我々 | 論文 |
  |---|---:|---:|
  | EIS 22 輝線の median | **0.89** | 1.0 |
  | **AIA 94 Å Fe XVIII** | **0.93** | 1.0 |

  **分光器 (EIS, erg, SSW) と撮像 (AIA, DN, JSOC) という完全に独立な 2 台**が
  揃って 10% 低い。→ 装置でも処理でもなく、**論文がわずかに明るい場所を
  測っている**と結論できる。差は論文自身の誤差 ±22% の中に収まる。

**教えたい勘所**: 「一致したことより、合わない理由を説明できることが実力」。
そして **「独立な 2 つ目の測定を持ってくる」のが最強の切り分け手段**であること。
今回は AIA の Fe XVIII が EIS とは全く別ルートの検証になった。

## モジュール 6: 寄与関数と EM loci

**扱うこと**
- I_λ = (1/4π) ∫ ε_λ(n_e,T_e) ξ(T_e) dT_e、ξ(T_e) = n_e² ds/dT_e
- ε は CHIANTI（論文は v7、現在は v10/v11）。コロナ組成 (Feldman+1992)、
  CHIANTI 電離平衡 (Dere+2009)
- **EM loci**: ξ_loci = 4π I_λ / ε_λ。各輝線がどの温度に効くかが一目で分かる。
  DEM を解く前に必ず描く。ここで既に「4 MK にピークがある」が見えてくる。
- 密度依存性: Fe XIII 202.044/203.826 は密度診断ペア。
  論文でも I_obs/I_dem ~ 1.8 とずれる線。

### ★★ 3 実装を比べる（準備段階で検証済み・この演習が目玉）

同じ CHIANTI 9.0.1 の ASCII ファイルを 3 者に読ませて G(T) を比べた
（`scripts/idl/09_gofnt.pro`, `scripts/gofnt_fiasco.py`, `scripts/gofnt_chiantipy.py`）:

| 実装 | 単位の約束 | CHIANTI IDL との比 |
|---|---|---|
| CHIANTI IDL `emiss_calc` | hc/λ × N_j × A_ji（**4π で割らない**） | 1.000 |
| fiasco `contribution_function` | 同上（4π で割らない） | 0.972 – 1.035 |
| **ChiantiPy `ion.emiss()`** | **sr⁻¹（4π で割ってある）** | **0.077 – 0.082** |

**ChiantiPy だけ 1/(4π) = 0.0796 倍ずれる。** 4π を掛け戻せば
median 1.000（0.968–1.030）で他の 2 者と一致する。

**なぜこれが目玉か**:
- **エラーが一切出ない。** 静かに 12.6 倍ずれた DEM が出てくる
- **全輝線が一律にずれる**ので、線ごとの ratio を見ている限り気づけない
- 気づくには「絶対値のオーダーが物理的に妥当か」を見るしかない
- DEM の絶対値は EM = n_e²L に直結するので、外すと
  **ループの長さや密度の議論が丸ごと狂う**

→ 受講者に「自分の G(T) が正しいオーダーか」を検算させる。
  活動領域なら EM ~ 10²⁷–10²⁹ cm⁻⁵、Fe XII 195.119 の G ピークは ~10⁻²³ erg cm³ s⁻¹。

### ★ 残る 3% の差は「準安定準位の占有数」に集中している（これも演習向き）

4π を補正すると **2 つの Python 実装は 4 桁一致**（0.999–1.000）し、
**IDL だけが最大 3.5% 違う**。温度ごとに見ると差は一様ではない:

| logT | Fe XIII 202.044 | Fe XII 195.119 |
|---|---:|---:|
| 5.80 | 1.003 | 0.999 |
| 6.20 | 1.035 | 0.994 |
| 6.80 | 1.166 | 0.982 |

**Fe XIII の 2 本が逆方向に動く**（202.044 が +3.5%、203.826 が −2.8%）。
合計はほぼ保存され、2 本の間で**再配分**されている。

輝線ごとに「全温度での比の幅」を並べると、
**大きい側は密度敏感線（Fe XIII 202/204、Fe XIV 264.787、Si X 258.375）**、
**小さい側は基底準位からの共鳴線（Fe IX、Ca XIV、Ca XVI、Ca XVII、Fe XV）**。

→ 差の正体は**準安定準位の占有数の扱い**（陽子励起、励起準位への電離・再結合）。
→ **これは Fe XIII が DEM で唯一大きく外れる（論文でも R = 1.80/1.90）
  ことの独立な説明になっている。** コードが違うだけで 3–12% 変わる線なのだから、
  原子データ自体の不確かさも同程度以上ある。

**受講者に伝えたいこと**: 「原子データの不確かさ」は抽象論ではなく、
**同じ DB を読む 3 つのコードを比べれば実際に測れる**。
そして不確かさが大きい線は、DEM で外れる線と一致する。

### どちらの Python 版を使うか → **fiasco**

| | fiasco 0.8.2 | ChiantiPy 0.16.0 |
|---|---|---|

## モジュール 7: DEM インバージョン

**扱うこと**
- DEM 逆問題は ill-posed。解は一意でない。誤差評価が本体。
- 論文の手法: **MCMC DEM** (Kashyap & Drake 1998, 2000; PINTofALE 付属)。
  関数形を仮定しない。強度を摂動させた 250 回の Monte Carlo で誤差評価。
- **Python に MCMC DEM の完全な等価物は無い**。代替:
  - `demregpy`（正則化インバージョン, Hannah & Kontar 2012）← 導入済み
  - 誤差の出し方も解の見え方も違う
- **これを隠さない**。「手法によって DEM がどう変わるか」自体を扱う。
  論文の Figure 6–8 と自分の結果を重ねて見せる。
- AIA Fe XVIII を拘束に加える。**ただし公式の AIA 94 応答は使えない**
  （低温線の寄与が入っている）。Fe XVIII + 連続放射のみの応答を作り直す。
  → **準備段階で作成済み**（`scripts/idl/15_aia94_fe18_resp.pro` +
    `scripts/aia94_fe18_response.py`）。CHIANTI の Fe XVIII 582 本を
    aiapy の波長応答に畳み込む。実際は **93.932 Å の 1 本が寄与の 100%**。
    R(T) のピークは **2.73e-27 DN cm^5 s^-1 pix^-1 at logT 6.90**。
  → これを入れないと **logT > 6.9 が拘束されず高温側の傾き beta が出鱈目**になる
    （PINTofALE のドキュメントが "toothpaste tube effect" と呼ぶ現象）。
- 誤差の入れ方: 論文の σ_I は約 22%（統計誤差 + 較正誤差）。
  箱内で数千ピクセル平均すると統計誤差は 0.1% 程度まで落ちるので、
  **較正の系統誤差を床として入れないと chi² が発散する**（準備段階で確認済み）。

**準備段階で得た実際の数値**（箱 y=[244:274] x=[32:40]、PINTofALE MCMC_DEM）

| | 我々 | 論文 |
|---|---|---|
| EM 分布のピーク | **logT 6.60 = 3.98 MK** | "strongly peaked near 4 MK" |
| alpha (logT 6.0-6.6) | **3.2-3.5** | 2.9 (Table 1 region 7) |
| beta (logT 6.6-7.0) | 4.0-4.4 | 9.0 |

- **R = I_obs/I_dem のパターンまで論文と一致する**:
  Fe XIII の 2 本だけ大きく外れ（論文 1.80/1.82、我々 1.28/2.81）、
  Ar XIV / Ca XIV / Ca XV が揃って 1.3-1.5（論文 1.36/1.31/1.43、
  我々 1.70/1.53/1.40）。
- **温度ビンは 0.1 dex にすること**。0.05 dex（35 ビン）だと輝線 22 本に対し
  劣決定になり、DEM が隣同士で 1-2 桁跳ねる。
- `mcmc_dem` が返す `dem` は **chi2 最小の 1 実現**なので凸凹する。
  論文が描いているのは MCMC アンサンブルなので `simdem` から中央値を取る。

**見せたい結論**: DEM が 4 MK 付近に強くピークを持つ（α ~ 3–4）。
これが「コアの高温プラズマはほぼ熱平衡＝加熱は高頻度」を意味し、
Parker のナノフレア描像（α ≲ 2 の広い分布を予言）への挑戦になる。

**教えたい勘所**: 「DEM は測定値ではなく推定値。誤差と手法依存性まで含めて結果」

## モジュール 8（発展）: Ca XVII のブレンド分離

- Ca XVII 192.858 は Fe XI 192.813 と O V 複合線に埋もれている
- 論文は Ko et al. (2009) の方法で分離
- **eispac にはこのブレンドを解くテンプレートが無い**（準備段階で確認）
  - `ca_17_192_858.1c` = 単一ガウシアン → 論文値の 4.75 倍が出る
  - `fe_11_192_813.2c`, `o__05_192_906.2c` = Fe XI + O V の 2 成分（Ca XVII 無し）
- → **自作テンプレートを作る**。→ **準備段階で完成済み**: `scripts/ca17_template.py`

| | Ca XVII 192.858 | 論文比 |
|---|---:|---:|
| eispac 同梱 `ca_17_192_858.1c`（1 成分） | 198.5 | **4.75** |
| **自作 5 成分テンプレート（Ko+2009 相当）** | **31.32** | **0.750** |
| （検証用）SSW/IDL 版 `08_fit_ca.pro` | 32.02 | 0.767 |

**Python だけで SSW の値を再現できる**ので、この発展モジュールは
Colab でも成立する。

### 設計（受講者に考えさせたい点）

- **分離できない成分は統合する。** サンプリング 0.0223 Å/画素、線幅 σ≈0.030 Å に対し
  O V の 192.797/192.801（0.004 Å 差）と 192.904/192.911/192.915（0.011 Å 差）は
  **原理的に分離不能**。強度重み付き波長で 1 本にまとめる。
  → O V 3 群 + Fe XI + Ca XVII = 5 成分。
  「成分を増やせば良くなる」わけではない、というのが要点。
- 自由パラメータは **O V スケール / 共通シフト / Ca XVII 振幅 /
  Ca XVII 中心 / 背景 の 5 つだけ**。あとは原子データと他の輝線から固定する:
  - O V の成分間比 = CHIANTI の分岐比（`scripts/idl/05b_ca17_ratios.pro`）
  - Fe XI 192.813 の強度 = 同じ箱の Fe XI 188.216 × 0.20896
  - Ca XVII の線幅 = Ca XIV 193.874 の線幅（論文 p.6）
  - Ca XVI 208.604 の線幅 = Ca XV 200.972 の線幅（論文 p.6）

### ★ 実装で必ず踏む罠（教材の目玉）

1. **背景の初期値を 0 にすると全パラメータが 0 で返ってくる。**
   eispac は `scale_guess()` で `scale = bkg_data / bkg_guess` を計算するので
   ゼロ除算 → inf → MPFIT が status = **-16** で即死する。
   しかも例外は出ず、静かに 0 が返る。
2. **`fixed=1` は効かない。`tied` に定数リテラルを書く。**
   `scale_guess()` は fixed を無視して全ガウシアンの振幅を
   「その波長でのデータ値 − 背景」に置き換えてしまう。
   `tied` は mpfit が反復のたびに強制するので上書きされない。
3. **強度を固定したいなら線幅も固定する。**
   I = A·σ·√(2π) なので、振幅だけ固定しても幅が動けば強度は変わる。
   実際、幅を自由にしたら Fe XI が 92 → 142 になった。

### eispac の `tied` の制約

- 公式サポート（`EISFitTemplate` の docstring に記載）。`0.41033*p[0]` なども通る。
- ★ **HDF5 に保存すると `tied` が `<U4`（4 文字）に切り詰められる。**
  長い式を使うテンプレートは**メモリ上で組み立てる**しかない
  （`EISFitTemplate(template=..., parinfo=...)`）。

受講者が自分の科学のために EIS を使うとき、**必ずこの種の作業が要る**。
既製テンプレートで済まない場面を一度経験させておく価値が高い。

### ★ 論文 Eq.(A1) の指数が誤植であることを実データで確定

論文 Appendix に印刷されている式は

    I_94warm = 0.39 * sum_{i=1}^{4} a_i * x^i ,   x = (f I_171 + (1-f) I_193)/116.54

だが、この字面どおりだと warm 成分が観測の 94 A 強度を桁違いに超える。
2011-07-02 の実データ (NOAA 1243 周辺 73 万ピクセル) で両方の読み方を比較:

| x の範囲 | 観測 I_94 | 字面どおり Σ aᵢxⁱ | 定数項つき3次式 aᵢx^(i-1) |
|---|---|---|---|
| 0–1   |  0.32 |   0.24 | **0.30** |
| 1–2   |  0.67 |   0.88 | **0.60** |
| 2–3   |  1.26 |   2.74 | **1.12** |
| 3–5   |  2.01 |   6.54 | **1.80** |
| 5–8   |  3.62 |  21.17 | **3.47** |
| 8–12  |  6.28 |  56.25 | **6.01** |
| 12–18 | 10.28 | 135.03 | **9.73** |
| 18–25 | 15.25 | 280.48 | **14.10** |
| 25–32 | 22.92 | 441.32 | **16.50** |

Fe XVIII 総強度 (>2 DN/s):
- 字面どおり → **1.37e3**（論文 6.18e4 の 1/45。しかも 77% のピクセルが負）
- 3次式版   → **7.68e4**（論文 6.18e4 とオーダー一致。負は 44%→ほぼ背景ノイズ）

**結論: 正しい式は定数項つきの 3 次式**

    I_94warm = 0.39 * ( a1 + a2*x + a3*x^2 + a4*x^3 )
    a = [-7.31e-2, 9.75e-1, 9.90e-2, -2.84e-3],  x は 30 で頭打ち

補強材料:
- x=1（中央値）で I_94warm = 0.389 になるのは**どちらの読み方でも同じ**なので、
  そこだけでは判別できない。実データを通して初めて決まる。
- 3 次式の極大は x = 27.4。論文の「30 で頭打ち」がちょうど折り返し付近で整合。
  （4 次式版の極大は 31.6 なのでこちらも一見それらしく見えてしまう。要注意）
- x=30 での warm は 16.2 DN/s。観測 I_94 の最大 ~30 DN/s と同程度で妥当。

→ `scripts/aia_fe18.py` に修正済み。この検証過程そのものが
  **講習会の最良の教材**になる（論文を鵜呑みにせず数値で確かめる例）。

### 事実（2026-08-06 時点で確認）

**PINTofALE 本体**
- 最新版は **v2.97 (2016-11-24)**。事実上凍結。
- **IDL v5 以上が必須**（商用ライセンス）。最小構成で 230 MB。

- MCMC DEM の本体は `MCMC_DEM()`。周辺に LINEID(), FITLINES(), MCMC_PLOT(),
  MCMC_ABUND() など。ドキュメント上の依存は IDL のみ。Python 版は存在しない。

**GDL（無料の IDL 互換処理系）で動くか**
公式 `doc/compatibility.txt` の記述:

- `initale` は 2 回実行できない
- 「GDL はコンパイル済みバイナリを restore する機能を持たない」
- **MCMC_DEM については何も書かれていない**

→ 重要な点: **MCMC_DEM はウィジェットではない**ので、動く見込みはある。
   しかも今回は輝線強度を eispac で出すので **FITLINES は不要**。

   **ただし未検証。**
   なお compatibility.txt は 2016 年頃の記述で、当時の GDL は 0.9.x。
   現在の GDL は 1.0.4 で互換性はかなり改善しているはずなので、
   この注意書きは悲観的すぎる可能性がある。

**この計算機での可否**
- IDL / GDL / SSW / module システム / sudo すべて無し
- conda-forge に GDL は無い（`gdl`, `gnudatalanguage` どちらもパッケージ実体なし）

**★ Colab では話が違う**
Colab は **root 権限がある**ので `!apt-get install gnudatalanguage` が通る。
つまり GDL 経路は、この計算機よりも **Colab の方が導入しやすい**。
これは要検証だが、もし通るなら「無料で PINTofALE の MCMC_DEM を回す」
経路が Colab 上に作れることになる。

### 5. 公式に AIA 用の MCMC_DEM スレッドがある

`doc/AIA_DEM.html`（2015-11-14 更新）が、まさに上の
「放射率を自分で用意して mcmc_dem に渡す」やり方の手本になっている。
Warren+2012 の EIS 輝線に置き換えればそのまま使える。要点:

```idl
; 温度グリッド
logTmin=4.0 & nT=41L & dT=0.1          ; 0.1 dex 刻み
emiss = dblarr(nT, nfilt)              ; ← ここに自前の応答/寄与関数を入れる
; ダミーの波長と原子番号（呼び出し形式のためだけ。放射率に畳み込み済みなら Z=1）
wvl = float(FILT) & Z = fix(0*wvl)+1
; 上限値フラグ
ulim = fix(0*wvl) & oo = where(flx le eflx, moo) & if moo gt 0 then ulim[oo]=1
; 初期 DEM と探索範囲（EM loci の最小値から作る）
emc = (abs(flx)##(fltarr(mot)+1))/emis
diffem = 0*logt + min(emc)
demrng = dblarr(mot,2) & demrng[*,0]=diffem/1d5 & demrng[*,1]=diffem*1d10
; 平滑化スケール（自由度 nu>1 になるよう調整せよ、と明記）
sampenv = dblarr(mot) & for i=0,mot-1 do sampenv[i]=stddev(emis[i,*])
smooscl = findscale(sampenv)
jnk = varsmooth(sampenv, smooscl, nueff=nueff, nutilde=nutilde)  ; ← nu を確認
; 本体
dem = mcmc_dem(wvl, abs(flx), 1d23*emis, Z=Z, logt=logt, diffem=diffem, $
      fsigma=eflx, ulim=ulim, nsim=nsim, nbatch=nbatch, nburn=nburn, $
      smoot=smoot, /noph, savfil=savroot+'_mcmc.save', $
      storpar=storpar, storidx=storidx, simprb=simprb, simdem=simdem, $
      demerr=demerr, simflx=simflx, simprd=simprd, nosrch=nosrch, $
      softlim=softlim, demrng=demrng, sampenv=sampenv, smooscl=smooscl)
; 収束確認: simprb のトレース → 実効サンプル数
rho = a_correlate(simprb,1) & n_eff = nsim*(1.-rho)/(1.+rho)
; 作図
mcmc_dem_whiskerplot, savroot+'_mcmc.save', cnum=0, cbox=33, cdot=0
```

このスレッドが強調している点は、そのまま講習会で言うべきことでもある:
- 誤差は Poisson より過分散。実務では **一律 10-20% の系統誤差**を仮定する。
- 平滑化は必須（Fredholm 第 1 種積分方程式なので高周波不安定）。
  自由度 nu > 1（データ点数 > 拘束されるパラメータ数）を必ず確認する。
- 出発点を変えて複数回走らせ、DEM の形が一致するか見る。
- ベストフィットを重視しすぎない。誤差帯で判断する。
- 感度範囲外に power が漏れる **"toothpaste tube effect"** に注意。

`pro/ssw/solar_tresp.pro`（TRACE/EIT/SXT/CDS/RHESSI の温度応答）、
`pro/ssw/hinode_xrt_emis.pro` も同梱されている。

### ★★★ Fe XII 195.119 の食い違いは私の平均処理のバグだった（despike でも較正でもない）

切り分けの手順と結論を全部残す。教材にそのまま使える。

1. **despike ではない**: `eis_prep, /nocr` で作り直した level-1 の
   箱内平均スペクトルは、despike 有りと**完全に同一**だった。
2. **フィッターではない**: IDL が吐いたスペクトルを Python (scipy curve_fit) に
   同じモデルで食わせても IDL と同じ答えになる。
3. **`wave_corr` の内挿が悪さをしていた（が主犯ではない）**:
   シフトをかけない素の平均と eispac を並べると、

4. **主犯**: `eis_getwindata` は欠損画素に **`wd.missing` = -100** を入れる。

  `cnt = 0` のサンプルはフィット窓からも外す。
- **`wave_corr` の内挿はしない**。EIS のサンプリングは 0.0223 Å/画素、
  線幅は σ ≈ 0.030 Å（σ あたり 1.3 点）しかなく、内挿は害の方が大きい。

### 実装の要点

- **分離できない成分は統合する。** EIS のサンプリングは 0.0223 Å/画素、
  線幅は σ ≈ 0.030 Å。O V の 192.797/192.801（0.004 Å 差）と
  192.904/192.911/192.915（0.011 Å 差）は**原理的に分離不能**なので、
  強度重み付き波長で 1 本にまとめる。
  → O V 3 群 + Fe XI + Ca XVII = **5 成分**。
  成分を増やしても情報は増えず、eispac の `min_points >= n_params` で弾かれる。
- 自由パラメータは **O V スケール / 共通シフト / Ca XVII 振幅 /
  Ca XVII 中心 / 背景 の 5 つだけ**（IDL 版と同じ）。

### ★ 踏んだ罠 3 つ（どれも原因が分かりにくい）

1. **背景の初期値を 0 にしてはいけない。**
   eispac は `fit_spectra` の中で `scale_guess()` を呼び、
   `scale = bkg_data / bkg_guess` で初期値をデータに合わせて伸縮する。
   背景の初期値が 0 だとゼロ除算で inf になり、MPFIT が
   **status = -16**（"parameter or function value has become infinite"）で
   即死して、全パラメータが 0 のまま返ってくる。

2. **`fixed=1` は効かない。`tied` に定数リテラルを書くこと。**
   `scale_guess()` は **fixed かどうかを見ずに**全ガウシアンの振幅を
   「その中心波長でのデータ値 − 背景」に置き換える
   （`scale_guess.py` の "compute new peaks" のループ）。
   一方 `tied` は mpfit が反復のたびに `exec('p[i] = <式>')` で強制するので
   上書きされない（`mpfit.py` の `tie()`）。
   → Fe XI の振幅は `tied="1293.148"` のように**定数リテラル**で固定する。

3. **強度を固定したいなら線幅も固定すること。**
   振幅だけ固定しても I = A·σ·√(2π) なので、線幅が動けば強度は変わる。
   最初 Fe XI の幅を O V と共有したまま振幅だけ固定したら、
   幅が 0.0439 まで太って強度が 92 → 142 になった。

### eispac の `tied` について（講習会で使える知識）

- **公式にサポートされている**（`EISFitTemplate` の docstring に記載）。
  `p[0] / 2` のような式が書ける。
- `fit_spectra` は eispac 同梱の mpfit を使い、`tie()` が
  `exec('p[i] = <式>')` で評価する。`0.41033*p[0]` や `p[1]+-0.1066` も通る。
- `generate_astropy_model.py`（astropy 経路）では
  `import` / `def` / `class` / `@` / `sys.` / `os.` / `subprocess.` が
  ブラックリストで弾かれる。
- ★ **HDF5 に保存すると `tied` が `<U4`（4 文字）に切り詰められる。**
  `0.41033*p[0]` のような式を使うテンプレートは
  **メモリ上で組み立てる**しかない（`EISFitTemplate(template=..., parinfo=...)`）。

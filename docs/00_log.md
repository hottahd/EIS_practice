### ★ 論文 Eq.(A1) の指数が誤植であることを実データで確定

論文 Appendix に印刷されている式は

    I_94warm = 0.39 * sum_{i=1}^{4} a_i * x^i ,   x = (f I_171 + (1-f) I_193)/116.54

だが、この字面どおりだと warm 成分が観測の 94 A 強度を桁違いに超える。
2011-07-02 の実データ (NOAA 1243 周辺 73 万ピクセル) で両方の読み方を比較:

| x の範囲 | 観測 I_94 | 字面どおり Σ aᵢxⁱ | 定数項つき3次式 aᵢx^(i-1) |
|---|---|---|---|
| 0–1   |  0.32 |   0.24 | **0.30** |
| 1–2   |  0.67 |   0.88 | **0.60** |
| 2–3   |  1.26 |   2.74 | **1.12** |
| 3–5   |  2.01 |   6.54 | **1.80** |
| 5–8   |  3.62 |  21.17 | **3.47** |
| 8–12  |  6.28 |  56.25 | **6.01** |
| 12–18 | 10.28 | 135.03 | **9.73** |
| 18–25 | 15.25 | 280.48 | **14.10** |
| 25–32 | 22.92 | 441.32 | **16.50** |

Fe XVIII 総強度 (>2 DN/s):
- 字面どおり → **1.37e3**（論文 6.18e4 の 1/45。しかも 77% のピクセルが負）
- 3次式版   → **7.68e4**（論文 6.18e4 とオーダー一致。負は 44%→ほぼ背景ノイズ）

**結論: 正しい式は定数項つきの 3 次式**

    I_94warm = 0.39 * ( a1 + a2*x + a3*x^2 + a4*x^3 )
    a = [-7.31e-2, 9.75e-1, 9.90e-2, -2.84e-3],  x は 30 で頭打ち

補強材料:
- x=1（中央値）で I_94warm = 0.389 になるのは**どちらの読み方でも同じ**なので、
  そこだけでは判別できない。実データを通して初めて決まる。
- 3 次式の極大は x = 27.4。論文の「30 で頭打ち」がちょうど折り返し付近で整合。
  （4 次式版の極大は 31.6 なのでこちらも一見それらしく見えてしまう。要注意）
- x=30 での warm は 16.2 DN/s。観測 I_94 の最大 ~30 DN/s と同程度で妥当。

→ `scripts/aia_fe18.py` に修正済み。この検証過程そのものが
  **講習会の最良の教材**になる（論文を鵜呑みにせず数値で確かめる例）。

  → **eis_auto_fit との突き合わせが要る**。これは SSW でしかできない。
- 全体に median 0.89（約 11% 低い）… 較正 + 箱の位置の残差。論文の
  誤差 σ_I が約 22% であることを考えれば十分に一致の範囲。

## 2026-08-06 — PINTofALE を使えるかの調査（ユーザーからの質問）

> PINTofALEは現状使えないの？

### 事実（2026-08-06 時点で確認）

**PINTofALE 本体**
- 最新版は **v2.97 (2016-11-24)**。事実上凍結。
- **IDL v5 以上が必須**（商用ライセンス）。最小構成で 230 MB。
- **公式サイトからのダウンロードは廃止**されている。
  サイトの記述: "Downloads through this website are now deprecated.
  The full install is now available through a shared MEGA folder.
  Contact us to get access to it."
  → 著者に連絡してMEGAの共有リンクをもらう必要がある。
- MCMC DEM の本体は `MCMC_DEM()`。周辺に LINEID(), FITLINES(), MCMC_PLOT(),
  MCMC_ABUND() など。ドキュメント上の依存は IDL のみ。Python 版は存在しない。

**GDL（無料の IDL 互換処理系）で動くか**
公式 `doc/compatibility.txt` の記述:
- 「ウィジェットを使うプログラム（FITLINES, LINEID 等）は動かない」
- CHIANTI 読み込み `read_wgfa2.pro`, `read_elvlc.pro` の書式指定から `$` を
  消すパッチが要る
- 環境変数 PINTofALE を必ず設定すること（自動検出が失敗する）
- `initale` は 2 回実行できない
- 「GDL はコンパイル済みバイナリを restore する機能を持たない」
- **MCMC_DEM については何も書かれていない**

→ 重要な点: **MCMC_DEM はウィジェットではない**ので、動く見込みはある。
   しかも今回は輝線強度を eispac で出すので **FITLINES は不要**。
   つまり「eispac で強度 → GDL の mcmc_dem に流す」という経路は原理的にあり得る。
   **ただし未検証。**
   なお compatibility.txt は 2016 年頃の記述で、当時の GDL は 0.9.x。
   現在の GDL は 1.0.4 で互換性はかなり改善しているはずなので、
   この注意書きは悲観的すぎる可能性がある。

**この計算機での可否**
- IDL / GDL / SSW / module システム / sudo すべて無し
- conda-forge に GDL は無い（`gdl`, `gnudatalanguage` どちらもパッケージ実体なし）
- apt には `gnudatalanguage 1.0.4-1build6` があるが **管理者権限が要る**
→ 現状このマシンでは検証できない。管理者に依頼すれば可能。

**★ Colab では話が違う**
Colab は **root 権限がある**ので `!apt-get install gnudatalanguage` が通る。
つまり GDL 経路は、この計算機よりも **Colab の方が導入しやすい**。
これは要検証だが、もし通るなら「無料で PINTofALE の MCMC_DEM を回す」
経路が Colab 上に作れることになる。

### 判断

- 講習会の **本線には置けない**。IDL ライセンス or 著者への個別連絡が要る時点で
  「多くの日本人研究者が触れるように」という目的に反する。
- ただし **発展モジュール／検証用の参照実装**としての価値は高い。
  論文と同じ手法で出した DEM が 1 つあれば、Python 側の結果を較正できる。
